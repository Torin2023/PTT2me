# Проверка фактической вставки на macOS

`tests/gui/` содержит самостоятельное приложение с `NSTextField`,
`NSSecureTextField` и `WKWebView` с HTML `input`, `textarea`, `contenteditable`
и `input type=password`. Rust bridge компилирует непосредственно
`src/inserter.rs` и `src/text_inserter.rs`: используются production AX-проверки,
Command-V и snapshot/restore, без подмены результата вставки.

## Сборка и запуск

Нужны Apple Silicon, macOS 13+, Command Line Tools и настроенный Rust toolchain.

```bash
bash scripts/test-insertion-gui.sh --build-only
bash scripts/test-insertion-gui.sh --preflight
bash scripts/test-insertion-gui.sh --run
```

Сборка создаёт `target/insertion-gui/InsertionFixture.app` (либо каталог внутри
настроенного Cargo target directory). Приложение имеет отдельный bundle ID
`com.ptt2me.insertion-fixture`, подписывается ad-hoc и не использует модель,
микрофон или установленный PTT2me. `--preflight` и `--run` используют ранее
собранный файл. После изменения исходников повторите `--build-only`.

Запускайте на выделенной разблокированной GUI-сессии. Для fixture нужны
Accessibility и разрешение отправлять события клавиатуры. Если macOS их
не предоставила, проверка завершится с кодом 2 (`BLOCKED`), без запроса или
изменения TCC. Выдать Accessibility этому `.app` можно вручную в System
Settings; новая ad-hoc сборка может потребовать повторного разрешения.
`--preflight` проверяет разрешения и наличие on-console сессии. Он не
подтверждает разблокированный экран или активное окно: `--run` отдельно
проверяет активацию окна и AX focus и завершается ошибкой, если они недоступны.

Во время `--run` приложение получает фокус и временно использует общий
clipboard. Не переключайте окна и не копируйте данные до завершения.
Проверки подтверждают, что AX focus принадлежит fixture, прежде чем вызвать
production Command-V. После завершения или ошибки приложение закрывает своё
окно и восстанавливает исходный clipboard, если его не заменил пользователь.
При внешнем изменении clipboard тест останавливается и сохраняет новые данные.
Закрытие окна, Quit, SIGINT и SIGTERM отменяют прогон через общую очистку и
записывают `FAIL`. Принудительное завершение процесса операционной системой
не может выполнить этот обработчик.

## Что проверяется

Двенадцать сценариев проверяют:

- Точный текст `AПривет. B` после вставки между `A` и `B` во всех четырёх
  обычных полях. В WebKit ожидается ровно одно событие `input`.
  Для `contenteditable` с обычным HTML white-space WebKit может представить
  пробел после точки как NBSP (U+00A0). В этом единственном месте допускаются
  две точные DOM-строки; в native/input/textarea требуется ASCII space.
  Фактический текст и допустимые строки записываются в JSON-отчёт.
- Выключенный `Пробел в конце`: `AПривет.B` в `textarea`.
- Смену фокуса после подготовки вставки, до Command-V: native → web и
  web → native. Старое поле остаётся `AB`, текст появляется только в новом.
- Отказ в нативном и HTML парольном поле как при начале операции, так и
  после смены фокуса перед Command-V. Пароль остаётся `secret`; предыдущий
  редактор не получает текст. Отказ на старте не изменяет даже changeCount.
- Сохранение всех clipboard items и представлений: plain text, RTF, TIFF,
  file URL, бинарный custom type.
- Сохранение новой копии, сделанной после Command-V до восстановления.

HTML/нативные setters используются только для подготовки `AB`/`secret` и
позиции курсора. Ожидаемый текст появляется исключительно через production
вставку. Ожидание восстановления берётся из production-констант; JavaScript
и ожидания конечного текста ограничены тайм-аутами.

## Результат и границы

`--run` выводит результаты сценариев и сохраняет
`target/insertion-gui/report-<UTC>.json`. Код 0 означает `PASS` всех сценариев,
1 означает ошибку сценария/очистки/записи отчёта, 2 означает отсутствие
условий запуска. `BLOCKED`, timeout и отсутствие отчёта не являются `PASS`.
Артефакты и отчёты остаются в игнорируемом `target/`.

CI выполняет сборку Rust bridge и Swift приложения. Полный обычный macOS gate
сохраняет `tests/pasteboard_main.rs`; fixture не включён в автоматический GUI
запуск CI, поскольку hosted runner не гарантирует интерактивную TCC-сессию.
Linux cloud не может собрать или запустить AppKit/WebKit fixture.

Fixture покрывает вставку и не подтверждает микрофон, распознавание, физическую
Fn/Globe, TCC-миграцию установленного приложения или поведение Chrome/Electron.
Проверка ChatGPT остаётся в
[`Manual P0`](../release/MANUAL_P0_CHECKLIST.md) для конкретного release candidate.
Эта задача добавляет проверку; заполненный Manual P0 получается только после
фактического ручного прогона установленной сборки.
