# Превентивная подготовка Accessibility

На успешном старте записи `runtime.rs` вызывает
`accessibility_preparation::prepare_focused_application`. Для выбора приложения
используется только PID `NSWorkspace.frontmostApplication`. Название приложения,
`bundleIdentifier`, список разрешённых приложений и постоянный кеш отсутствуют.

## Контракт

1. Единственный фоновый worker проверяет свежий system-wide `AXFocusedUIElement`:
   тип AXUIElement, принадлежность захваченному PID, обязательный строковый
   `AXRole` и необязательный строковый `AXSubrole`. Только ошибки unsupported
   (`-25205`) и no value (`-25212`) без возвращённого значения означают отсутствие
   необязательного атрибута. Другие ошибки и неверные типы не означают готовность.
2. При готовых метаданных worker сразу завершает работу. Это распространяется
   и на secure field: готовность метаданных не разрешает вставку в парольное поле
   и не доказывает, что элемент вообще редактируемый.
3. Если метаданные недоступны, worker читает только `AXRole`, `AXFocusedWindow`
   и ограниченные срезы `AXChildren` захваченного приложения. Возвращённые узлы
   проверяются на AX-тип и PID. Обход останавливается на `AXWebArea`, не читая
   потомков страницы. Текст, value, selection и URL не запрашиваются; focus и
   AX-атрибуты не изменяются. `AXUIElementSetMessagingTimeout` задаёт только
   тайм-аут IPC и не является setter для содержимого или фокуса.
4. После priming выполняется новый system-wide запрос фокуса. Диагностика
   содержит только статические `already_ready`, `ready_after_priming`,
   `unavailable` или `budget_exhausted`, без содержимого полей и имён приложений.
5. Подготовка возвращает runtime только дедлайн worker для ограничения ожидания;
   AX-узлы и результат готовности не передаются вставке. `text_inserter` сохраняет
   независимые свежие проверки фокуса и secure field при begin и перед paste,
   а также контроль владельца clipboard и безопасное восстановление.

Лимиты: общий дедлайн 500 мс; каждый IPC получает тайм-аут не более 50 мс,
ограниченный оставшимся временем. После foreign calls дедлайн проверяется снова:
поздний успех не принимается. Это best effort поверх macOS AX API, а не гарантия
жёсткого real-time прерывания зависшего системного вызова. Обход ограничен
128 уникальными узлами и глубиной 12; дубликаты и циклы отсекаются через CF equality.
Массивы обхода и запрашиваемые срезы children ограничены; role/subrole не копируются
в строки произвольной длины. Достижение лимита глубины или узлов консервативно
считается исчерпанием бюджета, если повторная проверка не показала готовность.

Single-flight guard освобождается при обычном завершении, unwind и ошибке создания
потока. Новый запрос во время активного worker пропускается, очередь подготовки
не создаётся. Ни дерево, ни фокус, ни статус приложения между записями не кешируются.

### Координация process-global AX timeout

По контракту Apple SDK `AXUIElementSetMessagingTimeout` на system-wide объекте
изменяет тайм-аут всего процесса. Поэтому worker и production-вставка используют
общий атомарный RAII lease: они не могут одновременно менять этот тайм-аут.
Runtime получает lease до свежего `text_inserter::begin` и удерживает его через
задержку clipboard до окончания свежей проверки в `paste`. После paste или ошибки
lease освобождается; ожидание восстановления clipboard не удерживает AX.

При занятом worker runtime оставляет текст в существующей одиночной очереди
вставки и повторяет попытку таймером через не более 10 мс (с учётом оставшегося
бюджета). Main loop не ждёт поток или mutex. Дедлайн 500 мс начинается до spawn;
после него занятый lease приводит к `preparation_busy_timeout` без AX-проб,
изменения clipboard и отправки Command-V. Точность доставки таймера определяется
run loop. Завершившийся worker позволяет обычную свежую вставку независимо от
результата подготовки. Generation/cancellation и защита уже активной paste/restore
транзакции сохраняются. Ошибка begin, paste, shutdown и unwind освобождают lease.
Это явная координация двух production-путей, а не предположение о длительности ASR
или об изолированности system-wide AX-объектов.
Для приложения без рабочего Accessibility этот механизм не гарантирует вставку.

## Автоматические проверки и границы доказательств

Модульные тесты проверяют PID-only dispatch, ready skip, cold→priming→recheck,
secure metadata без обхода, required/optional ошибки и типы, чужой PID, поздние
результаты начальной и повторной проверки, лимиты времени/узлов/глубины, циклы и
RAII single-flight. Runtime-тесты отдельно проверяют порядок worker→begin→paste,
удержание lease, ограничение повторов дедлайном, одиночную очередь, отмену поколения,
активную clipboard-транзакцию, сохранение дедлайна уже работающего worker при
повторном старте записи и освобождение при ошибке/shutdown/unwind.
AX application objects в тестах создаются локально только
для проверки типа/PID; тесты не активируют и не управляют окнами приложений.
Модель lazy AX детерминированная и не выдаётся за прогон реального браузера.

У dispatch нет параметра bundle ID и production-код его не читает. Поэтому
никакой из прежних идентификаторов не может выбрать отдельную ветку или исключить
приложение: любой положительный frontmost PID идёт в один и тот же механизм.
Это source-level доказательство маршрутизации, а не тест вставки текста.

| Приложение / прежний ID | Универсальный путь при наличии frontmost PID | Первая диктовка в реальном приложении |
| --- | --- | --- |
| Chrome stable — `com.google.Chrome` | Да, тот же PID-only dispatch | Не проверена |
| Chrome beta — `com.google.Chrome.beta` | Да, тот же PID-only dispatch | Не проверена |
| Chrome dev — `com.google.Chrome.dev` | Да, тот же PID-only dispatch | Не проверена |
| Chrome canary — `com.google.Chrome.canary` | Да, тот же PID-only dispatch | Не проверена |
| ChatGPT — `com.openai.codex` | Да, тот же PID-only dispatch | Не проверена |
| Yandex — `ru.yandex.desktop.yandex-browser` | Да, тот же PID-only dispatch | Не проверена |
| Неизвестный ID или отсутствие bundle metadata | Да, тот же PID-only dispatch | Не проверена |

Снимок 2026-09-18: plist в `/Applications` подтвердили Chrome 153.0.8010.48,
ChatGPT 26.915.31029 и Yandex 26.8.0.1829. Chrome Beta/Dev/Canary по стандартным
путям `/Applications/Google Chrome {Beta,Dev,Canary}.app` отсутствовали.
Это сведения об установленных bundle, не о запущенном процессе и не о доставке
Command-V. Установка недостающих приложений не выполнялась.

Полный automated gate: `cargo fmt --all -- --check`,
`cargo test --all-targets --features test-support -- --test-threads=1`,
`cargo clippy --all-targets --features test-support -- -D warnings`,
`cargo audit --no-fetch --deny warnings`. Локальный отчёт фиксирует точные команды,
коды завершения, source SHA и пути логов; прохождение этого gate не закрывает
проверки реальных приложений или Manual P0.

В текущем задании запрещены GUI automation, управление окнами и отправка
клавиатурных событий. Поэтому GUI fixture `--run`, внешний paste-режим,
переключение focus, продуктовый запуск и ручные cross-app сценарии не выполнялись.
Build-only fixture допустим и подтверждает только сборку.
