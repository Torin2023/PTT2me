# Автоматические проверки и выпуск PTT2me

По решению владельца от 2026-11-03 ручное тестирование полностью исключено из
требований публикации и релиза. Ручной P0, заполнение ручного чек-листа и
исключение для его пропуска не требуются. Это изменение процесса не означает,
что непроверенные сценарии стали PASS. Оно не отменяет автоматические gates,
разрешение владельца на merge/публикацию или ограничения подписи Preview.

Этот документ заменяет прежние требования ручного release gate в исторических
планах и спецификациях `docs/superpowers/`. История выпуска 1.3.2 сохраняется.

## Выбор наборов CI

Required check `Format, test, lint, and audit` запускается для каждого PR и push
в `main`, включая документацию. Workflow целиком не пропускается по `paths`:
это оставило бы required check в Pending. Ошибка или отмена job выбора проверок
завершает required check ошибкой, а не успехом с пропущенными шагами.

| Изменённые входы | Автоматические проверки |
| --- | --- |
| README, AGENTS, Markdown в docs, шаблоны задач/PR | Контракты CI и релизной документации, тесты выбора и проверки доказательств |
| `site/**` | Те же лёгкие проверки; build/tests, lint, static export в PR; на main это выполняет Pages, если срабатывает его path filter, иначе CI |
| `updates/releases/X.Y.Z.json`, `updates/channels/*.json` | Лёгкие проверки; при публикации Pages независимо проверяет подпись, модель, tag/source и реальные DMG |
| Rust, Cargo, toolchain, scripts/tests, assets, модель, trusted public key | Полный macOS gate либо допустимый результат идентичного полного прогона |
| Workflow, логика выбора/доказательств или неизвестный путь | Полный macOS gate и проверки сайта |
| `workflow_dispatch` | Все наборы, без повторного использования результата |

Git diff читается полностью, без лимита API в 300 файлов. Rename учитывается
как удаление и добавление; при неизвестной базе выполняются все наборы.
На push проверки сайта передаются Pages только при совпадении его path filter
и не более 300 изменённых файлах; в остальных случаях CI выполняет выбранный
набор сам. Соответствие фильтра Pages проверяется автоматическим тестом.
Полный PR diff используется для определения затронутых областей. Поэтому
version bump не исчезает из рассмотрения при следующем metadata commit.

## Когда полный прогон можно не повторять

`scripts/ci-validation.py` использует доказательство только из успешного
`ci.yml` этого репозитория. Нужны одновременно:

- SHA-256 всех tracked входов приложения, включая Git modes/paths/blob IDs,
  Cargo, toolchain, scripts/tests, CI, model manifest и trusted public key.
  Из fingerprint исключены только известные документация, сайт и release records;
  их проверки выполняются отдельно. Неизвестные пути включаются.
- Fingerprint фактически проверенного checkout, включая synthetic merge tree
  PR, совпадает с текущим. Отдельно через GitHub Git Trees проверяются входы
  исходного head producer и записанного tested SHA, поэтому другое содержимое
  workflow не может выдать принимаемое доказательство с произвольным заявленным hash. Различия только в
  merge base, которые нельзя подтвердить этим способом, запускают полный gate.
- Совпадают macOS `ImageOS`, `ImageVersion`, `RUNNER_ARCH` и актуальный HEAD
  RustSec advisory-db. Новый advisory или новый образ runner требует полного
  прогона, даже если исходники не менялись.
- По времени GitHub прошло не более 24 часов. Все шаги полного gate выполнены
  успешно; skipped/failed/cancelled не принимаются. Проверены repository,
  workflow, run ID/attempt, исходный SHA и время создания artifact.
- JSON получен из artifact конкретного запуска, ZIP digest совпал. Размер и
  список entries ограничены; архив не распаковывается в рабочую директорию.

Доказательство создаётся только после полного выполнения fmt, свежего строгого
RustSec audit, всех Rust-тестов, shell contracts, сборки AppKit/WebKit fixture и
Clippy. Повторно использованный результат не создаёт новое доказательство и
не продлевает его срок. Ссылка на исходный run сохраняется в job summary.

API недоступен, artifact отсутствует/повреждён/просрочен, источник fork,
несовпадение или неопределённость: выполняется полный gate. Просматриваются
последние 20 успешных runs; отсутствие подходящего среди них также означает
полный прогон. `actions: read` используется только для чтения provenance;
приватные ключи или release secrets CI не получает.

При совпадении этих условий результат PR может использоваться после merge.
Новые проверки после merge нужны, если изменились реальные входы или условия
доказательства. Для документации нельзя требовать локально повторять уже
подтверждённые Rust tests только из-за нового commit SHA.

## Автоматический release gate

1. Получить успешный required CI для текущего PR и подтверждение полного gate
   для входов binary source: новый прогон или проверенное повторное использование.
   Локальный полный Rust suite не дублирует уже подходящий CI без изменения входов
   или нового сбоя. При необходимости актуализировать RustSec используется
   `cargo audit --deny warnings`.
2. На контролируемом Apple Silicon Mac вызвать
   `scripts/build-release-artifacts.sh` с точной чистой source identity и
   внешними model/key inputs. Builder сам вызывает `scripts/release-preflight.sh`:
   отдельный повтор preflight не является обязательным. Его автоматический
   `pasteboard_main` сохраняется, как и проверка соответствия Ed25519 ключей.
3. Создать локальный `vX.Y.Z` на binary source, не перемещая существующий tag.
   Выполнить `scripts/verify-release-artifacts.sh --expected-tag vX.Y.Z` для
   закрытого набора из пяти файлов. Проверки signature, hashes/sizes, DMG,
   bundle identity, exact model, model smoke, codesign и Mach-O parity обязательны.
   Команды с полным набором аргументов приведены в README.
4. Сохранить результат вне Git: version/build/source, локальный tag, fingerprint
   входов, пути и SHA-256/размеры пяти файлов, использованный verifier и окружение.
   Не повторять build/verifier из-за правок описания или сайта. При изменении
   любого артефакта, tag/source, ключа, model manifest, verifier, существенного
   окружения или неполном результате проверка выполняется заново.
5. После отдельного разрешения владельца опубликовать точные проверенные файлы
   и tag. Сверить remote tag, скачать публичные assets и сравнить размеры/SHA-256.
   Pages повторно проверяет доставленные DMG, Ed25519 signature, model manifest,
   immutable record и tag/source, затем строит/проверяет сайт и публикует канал.
   Эти проверки доставки не заменяются доказательством исходного CI.
6. Проверить публичные сайт, stable/immutable records и неизменность trusted key.
   В release notes указать выполненные автоматические проверки и границы покрытия.

Preflight/build/verifier сами ничего не публикуют. Запреты изменения модели,
доверенного ключа, TCC, проверки подписи обновлений и обхода Gatekeeper сохранены.
Отсутствие Apple Developer ID не отменяет ad-hoc codesign checks или Ed25519.

## Что автоматизация пока не подтверждает

- Установку и replacement через Finder, первый запуск установленного app,
  реальную выдачу/отзыв/миграцию TCC и отображение иконки в пользовательской среде.
- Физическую Fn/Globe и назначенную клавишу на реальном оборудовании, системные
  combinations/autorepeat, потерю event tap в пользовательской сессии.
- Реальный микрофон, качество диктовки/ASR, длительные записи и сбои аппаратуры.
- Доставку текста и сохранение clipboard в текущих Chrome, Yandex, ChatGPT/Codex
  и других приложениях; secure fields и смену фокуса в этих внешних приложениях.
- Полный пользовательский цикл updater → открытие DMG → replacement → TCC.

Unit/integration tests проверяют соответствующие состояния, контракты и отказы;
`pasteboard_main` выполняет настоящий автоматический NSPasteboard round trip.
Fixture в CI только собирается. Model smoke подтверждает загрузку модели,
не качество речи. Эти результаты не являются доказательством перечисленных
сквозных пользовательских сценариев. Они остаются **непроверенными**, но не
создают требования ручного тестирования или ручного разрешения на его пропуск.
Запуск диагностического GUI fixture возможен отдельной задачей с нужными
разрешениями; он не входит в обязательный процесс выпуска.
