# Следующий Preview: 1.4.0

Кандидат следующей minor-версии после 1.3.2 — **1.4.0 Preview**. Пакет получает
новую версию после последовательной интеграции изменений PR #61–63 в ветке
кандидата. Source commit и build фиксируются перед сборкой. Опубликованные
GitHub Release, сайт и stable channel до отдельной публикации остаются на 1.3.2.

## Реализованные этапы

1. PR #61 выбирает автоматические проверки по изменённым входам и повторно
   использует только подтверждённый подходящий полный CI. Ручное тестирование
   полностью исключено из требований публикации и релиза.
2. PR #62 добавляет WER/CER и измерения задержек на закреплённом русском
   FLEURS-корпусе. Исходные записи, reference и полные JSON-отчёты остаются
   вне Git; методика и измерения — [`performance.md`](../performance.md).
3. Быстрый ASR-профиль с четырьмя потоками доступен по выбору; default остаётся
   двухпоточным. Настройка применяется после перезапуска. Восстановление
   ASR worker сохраняет профиль текущей сессии.
4. Production clipboard transaction проверяется с настоящим приватным
   NSPasteboard, включая восстановление исходных байтов, смену владельца,
   ошибку команды и Drop. GUI fixture в CI проверяется сборкой.
5. Типизированные ошибки вставки и обновлений отображаются статическими
   сообщениями без transcript, clipboard contents, window titles, URL и путей.
   Открытие уже проверенного DMG можно повторить без повторной загрузки.
6. Проверенный Full repair доступен из неактивных ошибочных состояний.
   FIFO preflight, запреты во время активной работы и владения clipboard,
   signature/size/SHA, quarantine и held-file verification сохранены.
7. Чистая политика fairness, deadlines и backoff вынесена из runtime без
   переписывания его AppKit-границ и существующих алгоритмов.
8. PR #63 обновляет зависимости сайта и production workerd renderer. На точном
   lockfile нет high/critical advisory; остаются 16 moderate dependency entries
   одного minimatch advisory в lint chains. Это не чистый audit. Детали и
   ограничения — [`SITE_DEPENDENCY_REFRESH.md`](SITE_DEPENDENCY_REFRESH.md).

## Подпись текущего Preview

По решению владельца от 2026-11-04 разработка и выпуск продолжаются с **ad-hoc
подписью**. Apple Developer ID и notarization в ближайшее время не планируются.
Их отсутствие не блокирует этот кандидат. PR #64 с отдельной политикой
Developer ID закрыт без слияния и не входит в текущий release source.
Исследование Apple membership и создание сертификатов/credentials прекращены.

Существующие `build-app.sh` и создание Update в `build-release-artifacts.sh`
используют `codesign --sign -`. Автоматические codesign checks, exact model,
Mach-O parity и остальные проверки bundle сохраняются. Preview нельзя
представлять как подписанный Developer ID или прошедший notarization.

Ed25519 отдельно подтверждает подлинность update manifest и его привязку к
точным размерам/SHA-256 DMG. Доверенный публичный ключ не меняется; применяется
существующий внешний приватный ключ. Проверки подписи, TCC и Gatekeeper не
отключаются. Ad-hoc подпись не подтверждает Apple developer identity.

## До публикации

1. Успешный required check для version/source кандидата: полный автоматический
   macOS gate или допустимое доказательство по
   [`AUTOMATED_RELEASE.md`](AUTOMATED_RELEASE.md). Ранее проверенные неизменные
   входы не требуют повторных локальных полных прогонов.
2. Сборка Full/Update из точного чистого source commit с фиксированными моделью
   и Ed25519 key; builder вызывает preflight один раз.
3. Локальный tag `v1.4.0` на binary source и независимый verifier закрытого
   набора из пяти файлов. Сохранить identity, hashes/sizes, окружение и логи
   вне Git. Документационные правки не требуют повторной сборки.
4. Подготовить release notes с выполненными проверками и границами покрытия.
   Merge, загрузка публичных DMG/tag, публикация GitHub Release и Pages
   выполняются в пределах отдельного разрешения владельца. PR approval
   автоматически не оформляется.
5. При публикации независимо проверить доставленные assets и remote tag;
   затем Pages проверяет release record, подпись и DMG до обновления канала.

Небольшая выборка read speech на одном Mac не подтверждает реальную диктовку
на всех микрофонах и устройствах. Native clipboard tests не доказывают
Command-V в сторонних приложениях, физическую Fn/Globe, выдачу/миграцию TCC,
Finder replacement или полный пользовательский updater cycle. Эти сценарии
остаются непроверенными и раскрываются в release notes; ручного тестирования
или исключения владельца для его пропуска не требуется.
