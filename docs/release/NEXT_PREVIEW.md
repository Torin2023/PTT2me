# Следующий Preview: последовательность подготовки

Цель — следующая minor-версия после 1.3.2, предварительно **1.4.0 Preview**.
Номер, source commit и build фиксируются после интеграции изменений и готовности
подписи. Этот план не меняет текущий опубликованный канал и не назначает дату
до устранения блокеров.

## Порядок изменений

1. Интегрировать PR #61: выбор автоматических проверок, подтверждённое повторное
   использование CI, полное исключение ручных release gates.
2. WER/CER и задержки на закреплённом русском FLEURS-корпусе. Исходные записи,
   reference и полные JSON-отчёты остаются вне Git. Методика и измерения —
   [`performance.md`](../performance.md).
3. Опциональный быстрый ASR-профиль при неизменном двухпоточном default.
   Настройка применяется только после перезапуска приложения. Восстановление
   дочернего ASR-процесса в текущей сессии сохраняет профиль, выбранный при запуске.
4. Проверки production clipboard transaction с настоящим приватным NSPasteboard
   в существующем автоматическом macOS target. GUI fixture остаётся build-only
   при действующем запрете управления окнами/клавиатурой.
5. Статические сообщения по типизированным ошибкам вставки и обновлений.
   Никаких transcript, clipboard contents, window titles, URL или путей в
   пользовательской диагностике.
6. Доступ к проверенному Full repair из неактивных ошибочных состояний.
   Сохранить FIFO preflight, отказ во время записи/распознавания и владения
   clipboard, проверку подписи/размера/SHA, quarantine и повторную проверку
   файла непосредственно перед открытием.
7. Отделить чистую политику планирования runtime от AppKit-эффектов, сохранив
   существующие проверки fairness, deadlines, backoff и FIFO.
8. После целевого полного автоматического gate интегрировать ветку разработки.
   Затем подготовить точные Full/Update release artifacts и выполнить
   [`AUTOMATED_RELEASE.md`](AUTOMATED_RELEASE.md). Merge и публикация выполняются
   только в пределах отдельного разрешения владельца; PR approval не требуется
   и автоматически не оформляется.

## Developer ID: установленный блокер

На Mac 2026-11-03 команда `security find-identity -v -p codesigning`, выполненная
также вне sandbox, вернула `0 valid identities found`. Доступная пригодная
**Developer ID Application identity с приватным ключом не обнаружена**.
Создание/импорт ключей, сертификатов, API credentials, принятие соглашений и
оплата не выполнялись. Нельзя объявлять будущую сборку подписанной Developer ID
или автоматически заменять это требование ad-hoc подписью.

Текущие `build-app.sh` и операция создания Update в
`build-release-artifacts.sh` явно используют `codesign --sign -`. Наличие
сертификата само по себе эти команды не изменит. Когда пригодная существующая
identity будет доступна, интеграция должна:

- Явно выбрать identity по fingerprint и ожидаемой команде разработчика;
  preflight должен отклонять отсутствие/неподходящий сертификат без fallback.
- Подписать вложенные dylib и executable, затем `.app`, после всех изменений
  Mach-O/Info.plist, с secure timestamp и Hardened Runtime. Отдельно проверить
  необходимые аудио-entitlements; не отключать library validation без причины.
- После удаления модели и изменения variant повторно подписать Update bundle
  той же identity. Проверить цепочку подписи, TeamIdentifier, runtime flags,
  точную модель, Mach-O parity и все прежние проверки bundle.
- Для нотариального выпуска использовать уже разрешённую аутентификацию Apple,
  дождаться принятия, прикрепить и проверить tickets. Создание новых credentials
  требует отдельного подтверждения. Hashes/размеры DMG и Ed25519 manifest
  вычисляются после всех изменений подписи/stapling.

Developer ID и Ed25519 решают разные задачи: доверенный updater key и проверка
manifest сохраняются. Подпись сертификатом не является доказательством успешной
нотаризации, миграции TCC или пользовательского replacement.

Источники: [сертификаты Developer ID](https://developer.apple.com/help/account/certificates/create-developer-id-certificates/),
[нотариальная проверка macOS](https://developer.apple.com/documentation/security/notarizing-macos-software-before-distribution).

## Границы готовности

Публикация не начинается до завершения всех реализуемых этапов, успешного
автоматического gate и доступности требуемой signing identity. При отсутствии
identity готовность к **Developer ID-релизу не подтверждена**; остальные работы
продолжаются независимо.

Небольшая выборка read speech на одном Mac не подтверждает реальную диктовку
на всех микрофонах и устройствах. Native clipboard tests не доказывают
Command-V в сторонних приложениях, физическую Fn/Globe, выдачу/миграцию TCC,
Finder replacement или полный пользовательский updater cycle. Эти ограничения
сохраняются в release notes, не превращаясь в требования ручного тестирования.
